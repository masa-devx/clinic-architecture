# 打ち合わせの記録

PdM とビジネスサイドの打ち合わせ（作る・作らないを決める）と、PdM とプロジェクトリーダーの打ち合わせ（仕様を詰める）を、1回1ファイルで残す。書くのは自分（エンジニアとして同席した立場で）。

面接で「なぜ作ると決めたのか」「なぜ作らなかったのか」「誰と何を調整したのか」を話すときの元になる。

## ファイル名

`<日付>-<要望の番号>-<短い名前>.md`（例：`2026-11-24-R-1-appointment-list.md`）。要望の番号は [clients.md](../clients.md) の3章。

## 形

```markdown
# 〇〇の打ち合わせ

- 日付: ／ 種類: 方針（PdM × ビジネスサイド）か、仕様（PdM × プロジェクトリーダー）
- 出た人: PdM・〇〇・エンジニア（自分）
- 要望: R-番号 ／ Issue: #番号

## 話したこと
<!-- 要望の中身・事実と仮説・出た意見（誰が、何を） -->

## 決めたこと
<!-- 作る・作らない・あとで・別の形。作るなら範囲と期限。仕様なら、詰めた所 -->

## 決めなかったこと・作らないこと（と、その理由）

## クライアントへの返し方
<!-- 方針の打ち合わせのとき。「今回は作りません。代わりに〇〇でできます」など -->

## 自分（エンジニア）が言ったこと
<!-- 手間・リスク・測れないこと・負債。誰の何が困るかの言葉で -->

## 次にやること（誰が・いつまでに）
```

架空の要望であることは、[clients.md](../clients.md) の注のとおり。
