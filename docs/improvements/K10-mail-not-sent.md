# K10. 予約は入ったのに、メールが出ないことがある

- 日付: 2026-11-18 ／ 段階: 5 ／ 関係する判断: [D-013](../decisions.md)

最初から outbox で作ったので（D-002）、「メールが出ない」素朴な作りは動かしていない。「前」の数字はない。守れていることを、テストで確かめた。

## 1. 症状（起こりうること）

予約をコミットしたあとに、メールを送る（か、ジョブを積む）形だと、そのあいだでプロセスが落ちたとき、予約だけが残って、メールは二度と出ない。

## 2. 測った

`apps/api/spec/services/notifications/notifications_spec.rb`。

```sh
docker compose run --rm api bundle exec rspec spec/services/notifications
```

## 3. 原因

「予約を入れる」と「メールを送る（積む）」が、別々の書き込みで、あいだに落ちる所がある。

## 4. 直した

送るメールの記録（outbox）を、予約と同じトランザクションで入れる。送るのは、あとから定期のジョブがする。比べた案と理由は D-013。

## 5. 数字

| 確かめたこと | 結果 |
| --- | --- |
| 記録を入れる所をわざと失敗させたとき、予約が入るか | 入らない（0件） |
| 送る所をわざと失敗させたとき、記録が残るか | 残る（`pending`・試した回数1）。6分後の実行で送られる |
| 送る処理を2回動かしたとき、メールは何通か | 1通 |
| 5回続けて失敗したとき | `failed` になり、それ以上は試さない |

測った条件: RSpec の中（テスト用の DB・メールは送らずにためる設定）。手元の Docker で E2E を流したときは、予約とキャンセルのメール6通が Mailpit に届き、outbox は6件とも `sent`、ジョブの失敗は0件（1回）。

「送ったあと、送信済にする前に落ちる」（2回送られる場合）は、テストで起こしていない。

## 6. 再発防止

上のテストが、RSpec の中で毎回走る。
