# 語れる記録（面接で話す形）

1つの Issue を終えるたびに、1件書く。書くのは自分（AI に書かせない。[tech-lead](../../agents/skills/tech-lead/SKILL.md) の7章で、面接官の役に深掘りしてもらってから直す）。

[decisions.md](../decisions.md) は「何を決めたか」の記録、ここは「**誰の何を、なぜ、どう解いたか**」を話すための記録。

## 守ること

- **架空の現場であることを書く**。会社・関係者・事業の数字は [company.md](../company.md) の作りもの。話すときも「個人開発で、架空の現場を想定して」と言う
- **確かめた数字と、推測の数字を分ける**。計測用のデータ（`bin/rails bulk:load`）で測った数字は、測った条件を添える
- 技術の言葉だけで終わらせない。誰が困っていて、何が良くなったかを、技術を知らない人にも分かる言葉で1回言う
- 実務の話（前の現場の会社・コード・数字）は書かない（このリポジトリは public）

## ファイル名

`<課題の記号>-<短い名前>.md`（例：`E-1-appointment-list.md`）

## 形

```markdown
# 〇〇（誰の、何を、どうしたか）

- 課題: E-1 ／ Issue: #番号 ／ PR: #番号 ／ 判断: D-番号
- 舞台: 個人開発。架空の会社（docs/company.md）の現場を想定

## 一言で（30秒）

## 状況
<!-- 会社・チーム・自分の役割。どんな声から始まったか -->

## 課題
<!-- 誰が・いつ・どのくらい困っていたか。事実と推測を分ける。事業のどの数字に効くか -->

## 制約
<!-- 期限・止められないもの・人手・お金 -->

## 比べた案
| 観点 | 案A | 案B | 何もしない |
| --- | --- | --- | --- |
| 解けること | | | |
| 手間（作る・学ぶ・運用） | | | |
| 壊れ方 | | | |

## 選んだ理由と、捨てたもの
<!-- この規模・このチームで、なぜそれか。選んだ案の弱点と、それでも選んだ理由 -->

## やったこと
<!-- 自分がやったこと。順番に。いちばん難しかった所 -->

## 結果
<!-- 前と後の数字（測った条件）。推測なら推測と書く。確かめた方法 -->

## 失敗と学び
<!-- 外れた仮説・やり直したこと。次にやるなら何を変えるか -->

## 想定問答
<!-- 面接官の役に聞かれて詰まった問いと、その答え -->

  - A:
```
