# このリポジトリの目的

学習用。公開して運用するサービスではない。

## 何を作るか

架空のオンライン診療の「予約 → 受付 → 診察 → 会計」を、Ruby on Rails＋GraphQL＋PostgreSQL と、Next.js＋Chakra UI＋Apollo Client で作る。

## 何が分からないか・何を確かめるか

既存の型に沿って読んで直すだけでは分からないことを、自分で一から作って確かめる。次の3つ。

| 確かめること | 中身 |
| --- | --- |
| バックエンドの設計 | テーブル設計・インデックス・JOIN・トランザクション・同時更新・N+1・実行計画（EXPLAIN）・API の設計・外部のサービスが失敗したときの守り方 |
| フロントエンドの設計 | 画面の表示速度・API との通信・状態管理・コンポーネント設計・テスト・開発効率と、層と依存の向き |
| アーキテクチャと、課題の改善 | 構成と層を、比べた案と理由つきで決める。起こりうる課題（二重予約・N+1 など）を、設計とテストで先に防ぎ、守れていることを確かめる |

## 進め方

**最初から、きちんとした設計で作る**（2026-11-17 に変更。判断は [decisions.md](decisions.md) の D-002）。素朴な形を先に作って困らせる、という順番は取らない。二重予約を防ぐ制約・N+1 の対策・インデックス・カーソル・認可・層の分割・エラーの設計は、その機能を作るときに一緒に入れる。

まず、段階1（ログイン・診療枠・予約・キャンセル・予約の一覧が、画面から通る）までを、止まらずに作る。段階は [roadmap.md](roadmap.md)。

## 守ること

- **設計の理由を残す**。素朴な形を経ないので、「入れなかったら何が起きるか」は、テスト（同時に20リクエスト・クエリの本数の上限・他院の ID で取る）と設計の記録で説明できるようにする
- **段階1までは、解説で止まらずに作る**。解説（[explain-step](../agents/skills/explain-step/SKILL.md)）と実装の記録（[explain-change](../agents/skills/explain-change/SKILL.md)）は、動いたあとにまとめて作る。段階2より先の進め方は、段階1が終わってから決める
- **実務を持ち込まない**。実務のコード・プロダクト名・社名・お客さまのデータ・画面・仕様を使わない。一般的なオンライン診療として、自分で考えて設計する
- **確かめたことの出どころを書く**。ここで分かったことは「個人開発で作って確かめた」こととして書く。測った条件を添える
- **判断と数字を残す**。比べた案・選んだ理由・弱点は [decisions.md](decisions.md)、課題と前後の数字は [improvements/](improvements/README.md) に書く
- 秘密の値（決済のキーなど）を、コード・ログ・テストの出力に出さない。テストは偽の値で動かす
