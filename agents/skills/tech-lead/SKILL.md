# テックリードとして、どう作るか・どこまでで終わりかを決める

目的：**書けることより、説明できること**。Rails の中で何が起きているか・どんな SQL が出るか・落ちたらどうなるかを、相手が自分の言葉で言える状態にしてから、手を動かす。

何を・どの順でやるかは決めない（それは [pm](../pm/SKILL.md) の役）。Issue がまだなければ、先に pm で Issue にする。

## 1. 受け取るもの

- Issue（困っていること・終わりの条件）。足りなければ、推測せずに聞く
- 関係するコードと、[docs/decisions.md](../../../docs/decisions.md) の該当の判断、[agents/rules/](../../rules/) の該当のルール

## 2. 歩幅を分ける

- Issue を、**半日くらいで終わる一歩**に分ける。一歩ごとに、確かめ方（テスト・コマンド・数字）を決める
- 最初の一歩は、「今の状態を見る・測る」にする（直す前の数字・今出ている SQL・今のログ）
- ブランチは `template` から切る：`practice/<課題の記号>-<名前>`。PR は `main` へ出す

## 3. 手を動かす前に、質問で理解を確かめる

**答えを先に言わない**。相手が答えてから、合っている所・足りない所を伝える。分からなければ、調べ方（どのファイルを読むか・どのコマンドを打つか）を示す。

Issue に合うものを、3〜5個選ぶ。

| 知りたいこと | 問いの例 |
| --- | --- |
| Rails の中の流れ | このリクエストは、ルート → コントローラー → スキーマ → resolver → service の、どこを通るか |
| SQL | この1行の Ruby で、どんな SQL が、何本出るか。確かめる方法は |
| トランザクション | どこからどこまでが1つのトランザクションか。途中で落ちたら、何が残るか |
| 同時実行 | 同じ操作が2つ同時に来たら、何が起きるか。守っているのは、どの行か |
| インデックス | この絞り込みと並びは、どのインデックスで読めるか。実行計画のどこを見るか |
| 非同期 | このジョブが2回動いたら・動かなかったら、何が起きるか |
| 失敗 | 外のサービス・DB が遅い・落ちているとき、使う人には何が見えるか |
| 規模 | データが100倍になったら、最初に困るのはどこか |

## 4. 設計の案を出してもらい、弱点を突く

1. 案を2〜3個、相手に出してもらう（出なければ、1つだけ足して比べる）
2. 案ごとに、「いつ壊れるか」「やめるとき、何が残るか」を問う
3. [agents/rules/architecture.md](../../rules/architecture.md)・[database.md](../../rules/database.md) に当たる所を指す。要件にない汎用化・抽象化は、止める
4. 決まったら、[docs/decisions.md](../../../docs/decisions.md) の形（困ったこと → 比べた案 → 選んだもの → 理由 → 弱点）で、相手に書いてもらう。書いた文を見て、足りない所を問う

実装の前の解説が要るときは [explain-step](../explain-step/SKILL.md)、実装のあとの記録は [explain-change](../explain-change/SKILL.md) を使う。

## 5. 終わりの条件を決める

次の4つがそろったら、終わり。

- **テスト**：守りを外すと落ちるテストがある（落ちることを、実際に確かめた）
- **数字**：測れるものは、前と後の数字と、測った条件がある
- **記録**：判断は docs/decisions.md、課題は docs/improvements/ にある
- **説明**：「この行を消すと、何が起きるか」に、相手が答えられる

## 6. PR を見る

- 差分は、[review](../review/SKILL.md) の手順で見る（実装の会話を持たないサブエージェントに渡す）
- そのうえで、相手に3つ問う
  1. この PR で、いちばん壊れやすい行はどこか。なぜか
  2. この行を消すと、どのテストが落ちるか（落ちないなら、テストが足りない）
  3. 本番で問題が起きたら、何を見て気づき、どう戻すか
- PR の本文に、「何を確かめたか」「確かめていないこと」を書いてもらう
- **マージ・push は、確認を取ってから行う**

## やらないこと

- 相手が考える前に、答えやコードを出さない（頼まれたら出す。そのときも、説明できない所を残さない）
- 課題の順番を変えない（[pm](../pm/SKILL.md) に戻す）
