# 実装のあとに、解説して記録する

目的：AI が書いたコードを、自分で説明できる状態にする。説明できない所が残ったら、その一歩は終わりにしない。

## 1. 差分を読む

- `git diff` と、まだ追跡していないファイル（`git status --short`）。コミット済みなら、その一歩の範囲のコミット
- 対応する解説のページ（`docs/steps/<段階>-<連番>-<名前>.md`）と、[docs/decisions.md](../../../docs/decisions.md) の該当の判断

## 2. もう一度測る

- 解説のページの「残す数字」を、直す前と同じ条件（データの件数・同時の数・手元の環境）で測る
- 測れなかったものは、測れなかったと書く。推測の数字を書かない

## 3. 解説のページに「実装の記録」を足す

1. **変えたファイル**：ファイルごとに、何をしているかを1〜2行
2. **流れ**：1つのリクエストが、画面から DB まで、どこを通るか（番号つき。ファイルと関数の名前を書く）
3. **読んでほしい所**：大事な行を3〜5か所。なぜその書き方かを書く
4. **解説と違った所**：実装して分かったこと・案を変えた所
5. **前と後の数字**
6. **自分で説明できるかの問い**：3つ。答えは書かない
   - このコードの、この行を消すと何が起きるか
   - 同じことを、別の書き方ですると、どうなるか
   - テストは、何を確かめていて、何を確かめていないか

## 4. 記録を書く

- [docs/improvements/](../../../docs/improvements/README.md) に、課題と改善を1件書く（K・F の番号があるとき）。一覧の表にも1行足す
- [docs/decisions.md](../../../docs/decisions.md) の該当の判断に、「確かめた数字」を入れる
- 仕様や選定が変わったら、[docs/requirements.md](../../../docs/requirements.md)・[docs/roadmap.md](../../../docs/roadmap.md) を直す
- `docs/steps/README.md` の状態を「記録した」にする

## 5. 伝える

- 変えたこと・前と後の数字・未検証の範囲を短く伝える
- 「3つの問いに答えられるか、声に出して1分で説明してみてください」と伝える
- 次の一歩を1つ提案する。頼まれるまで、次へ進まない

## 終わりの条件

- 解説のページに「実装の記録」がある
- 数字は、測ったものだけが入っている
- 目次の状態が「記録した」になっている
