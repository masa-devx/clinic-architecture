# 実装の前に、一歩ぶんの解説を作る

目的：一気に作らず、なぜ入れるのかを理解してから進む。このスキルでは**実装しない**（アプリのコード・マイグレーション・テストを書かない）。

## 1. どの一歩かを決める

- [docs/steps/README.md](../../../docs/steps/README.md) の目次を読む
- 番号やテーマを言われたらそれ。言われなければ、状態が「未着手」の一番上を提案して、確認を取る
- 目次にないテーマなら、どの段階に入れるかを提案して確認を取る

## 2. 前提を読む

- [docs/product.md](../../../docs/product.md) の「守ること」。わざと後回しにしているものを、解説の中で先に入れない
- [docs/roadmap.md](../../../docs/roadmap.md) の、その段階の「理解すること」「残す数字」「比べる」
- [docs/requirements.md](../../../docs/requirements.md) の、関係する機能・守ること（R の番号）・課題（K・F の番号）
- フロントエンドの一歩なら [docs/frontend.md](../../../docs/frontend.md)
- [docs/decisions.md](../../../docs/decisions.md) と、それまでの一歩のページ。前の判断と矛盾しないようにする
- 今のコード・マイグレーション・スキーマ（あれば）。今の形を図に含める
- 秘密の値のファイル（`.env` など）は読まない

## 3. 解説を書く

`docs/steps/<段階>-<連番>-<名前>.md` に書く。同じ名前があれば上書きせず、確認を取る。文は短く、専門用語は説明してから使う。

1. **この一歩でできるようになること**（2〜3行）
2. **先に知っておく言葉**（1つ1〜2文）
3. **図**（Mermaid で1〜3枚。テーブルの関係は `erDiagram`、処理の流れは `flowchart`、同時に来るリクエストや API とのやり取りは `sequenceDiagram`）
4. **今の作りと、困ること**：素朴な作りのままだと何が起きるか。**どう起こすか**（データを増やす・同時に送る・途中で落とす・画面を操作する）と、**どう測るか**（クエリのログ・`EXPLAIN (ANALYZE, BUFFERS)`・テスト・ネットワークのタブ・Lighthouse）を、手順で書く
5. **案の比較**：2〜3案。案ごとに、良いところ・弱いところ・向いている場面。おすすめを1つ、理由つきで書く。手本にする構成（[roadmap.md](../../../docs/roadmap.md) の「手本」の列）と違う道具を選ぶなら、違いを書く
6. **小さな見本**：直す前と直したあとを、それぞれ10〜20行まで。全部は書かない。SQL が変わるなら、流れる SQL も並べる（推測で書かず、分からなければ「実装のときに確かめる」と書く）
7. **罠**：間違えやすい所
8. **6つの問い**：答えは書かず、問いだけを書く。下に「自分の答え」の欄を空けておく
   - なぜそうするのか
   - ほかの方法は
   - 弱点は
   - 問題が起きたら（どう気づき、どう直すか）
   - データが10倍・100倍になったら
   - 手本にする構成では、どうなっていそうか（分からなければ「分からない」でよい）
9. **残す数字**：前と後で、何を測るか

目次（`docs/steps/README.md`）の状態を「解説だけ」にする。

## 4. 伝えて、止まる

- 書いたファイルの場所と、要点（できるようになること・おすすめの案と理由・罠）を短く伝える
- 「4 の手順で、困ることを自分で起こして、数字を見てください。そのあと、6つの問いに自分の言葉で答えを書いてください。分からない所は聞いてください。書けたら『実装して』と言ってください」と伝えて止まる
- 返事がないまま、実装に進まない

## 5. 実装を頼まれたら

- 「自分の答え」の欄が空なら、実装の前に、書くかどうかを聞く（答え合わせをしてから進む）
- 答えに誤解があれば、実装の前に直す。直した所を解説のページに足す
- 判断を [docs/decisions.md](../../../docs/decisions.md) に1件書く（「前」の数字を入れる）
- 確かめたいことを先にテストで書き、失敗することを確かめてから実装する
- 終わったら [explain-change](../explain-change/SKILL.md) へ進む

## 終わりの条件

- 解説のページに、1〜9 がそろっている
- Mermaid の図が描ける
- 目次の状態が「解説だけ」になっている
- わざと後回しにしているものを、先に入れる内容になっていない
